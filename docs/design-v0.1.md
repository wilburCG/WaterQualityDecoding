# WaterQualityDecoding 水质解码器 — 项目设计 v0.1

> 创建：2026-10-08 by Mose
> 状态：草案，待 Wilbur 的水质分析报告到位后细化指标与解读规则

## 一、项目定位

面向公众的**水质科普与信息分享平台**，做三件事：

1. **解码报告**：把专业水质检测报告翻译成普通人看得懂的结论
2. **众包分享**：让大家在地图上分享自家周边河流的水质检测结果
3. **知识问答**：可持续积累的水质/水处理知识库 + 智能体，免费检索查询

一句话介绍：**「上传一份报告，看懂一条河；问一个问题，了解水的一切。」**

## 二、目标用户与场景

| 用户 | 场景 | 核心诉求 |
|---|---|---|
| 沿河居民 | 家附近有河，关心有没有污染 | 看地图上附近的实测分享 |
| 检测者/环保志愿者 | 手里有检测报告或试剂检测结果 | 上传 → 获得解读 → 分享给别人 |
| 普通公众 | "自来水有水垢正常吗""氨氮超标什么危害" | 免费问智能体，得到靠谱、有出处的回答 |
| 学生/科普受众 | 想了解水质指标、净水工艺 | 浏览指标百科与科普内容 |

## 三、核心功能

### 1. 报告解码（核心差异化）
- 支持多种输入：PDF 报告、报告照片、Excel 数据表、手工录入
- 处理流程：OCR/解析 → 指标结构化抽取 → 对照国标评价 → 通俗化解读
- 每份报告输出：
  - 综合水质类别判定（如地表水 Ⅰ–Ⅴ 类）
  - 逐项解读：指标是什么、实测值、标准限值、是否超标、可能来源、对健康/生态的影响
  - 「一句话总结」+ 可分享的解读卡片（图片）

### 2. 众包河流水质地图
- 地图按点位展示用户分享的检测结果，水质等级用颜色标注
- 时间轴：同一点位的水质变化趋势
- **数据可信度分级**：专业机构检测 > 便携式仪器 > 家用试剂 > 主观描述，显著标注
- 每条数据附免责声明：众包数据仅供参考，非官方结论

### 3. 水质知识智能体（免费）
- RAG 知识库，回答必须**附出处**，杜绝模型瞎编：
  - 《地表水环境质量标准》GB 3838-2002
  - 《生活饮用水卫生标准》GB 5749-2022
  - 《地下水质量标准》GB/T 14848-2017
  - 水处理工艺、常见污染物、家用净水知识
- 知识库可持续扩充：新研究、新闻、地方标准经审核后入库（"不管积累新知识"）
- 无人提问时也支持关键词检索文档原文

### 4. 科普内容
- 指标百科：pH、溶解氧、COD、氨氮、总磷、总氮、重金属、浊度、硬度……
- 净水常识：自来水工艺、净水器怎么选、水垢、余氯味道等
- 误区辟谣

## 四、技术架构（初稿）

```
用户端(Web/移动H5, Next.js)
   │
   ├── 报告上传 → API(FastAPI) → OCR(PaddleOCR) → LLM结构化抽取 → 评价引擎
   ├── 地图服务 ← PostgreSQL + PostGIS（点位/样本/测量值）
   ├── 知识问答 → RAG(embedding + rerank + LLM，引用溯源)
   └── 对象存储(MinIO/OSS)：原始报告文件
```

- 前端：Next.js + Tailwind；地图用高德 JS API（国内合规且友好）
- 后端：FastAPI + PostgreSQL + PostGIS + pgvector（或独立向量库）
- 部署：Docker Compose（复用 FlexWorker 运维经验）
- 评价引擎做成**确定性规则**（指标 × 标准限值映射表），LLM 只负责通俗化表达——水质判定不能让模型自由发挥

## 五、数据模型（初版）

- `sites` 点位：河流名、点位名、经纬度、水体类型（河流/湖库/地下水）
- `samples` 检测分享：用户、点位、采样时间、检测方式、综合类别、报告文件、审核状态
- `measurements` 指标测量值：sample_id、指标 code、数值、单位、对应限值、是否超标
- `indicators` 指标字典：名称、别名、单位、各标准限值、百科说明
- `knowledge_docs` / `knowledge_chunks`：知识文档与切片（向量）
- `qa_logs`：问答记录（用于优化与成本监控）

## 六、分期建议

- **M1（最小闭环）**：手工录入/上传数据 → 自动评价 + 通俗解读；指标百科页
- **M2**：众包地图 + 分享卡片 + 用户体系
- **M3**：知识智能体 RAG 问答（国标库先行）
- **M4**：PDF/照片 OCR 自动抽取、移动端体验优化、内容审核与运营后台
- **M5（可选）**：接入官方公开监测数据做对照、河流订阅与变化提醒

## 七、需要 Wilbur 决策的问题

1. 报告中实际检测了哪些指标、报告长什么样（**等附件**——决定 M1 的解读规则）

4. 是否引入官方地表水自动监测公开数据作为基准对照
